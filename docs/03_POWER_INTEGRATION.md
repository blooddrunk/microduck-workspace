# 03 · HAT、IMU、整机分级通电：从卸力到首次站立

> **这是后续阶段教程，不是“现在就把所有线插好”的指令。**
> 你目前尚未提交 HAT/IMU 具体型号、PCB 版次和电源实物图，因此**不提供未经验证的 pin-to-pin 接线命令**。完成 [00 盘点](00_START_HERE.md)、[01 主板单独启动](01_BOARD_BOOT.md)、[02 单舵机](02_SERVO_IMU.md) 后才实施本节。

## 分支兼容性先确定

**A · 官方 HAT + 飞特舵机**：官方 HAT 的半双工接口和 5V 供电不能推导出官方 Rust runtime 能理解飞特协议；必须有飞特适配的 `RobotIo` / bus 实现。原官方 `imu_to_dxl` 使用 Dynamixel 协议，飞特固件/IMU 接入另需核对。

**B · kissqy HAT + 同套飞特 IMU**：kissqy 提供已在作者样机上验证的 HD1910 镜像与运行时，但硬件 Rev、引脚、IMU 固件、部署模型合同要成套核实。下载的镜像默认服务可能会自动启动；**不允许第一次合闸就让 15 颗舵机上力**。

**C · 官方/自制 HAT + BNO085 I²C 等**：fanhao375 对这个组合有实际校准/运动记录，但其针对吻合固件版本的改动不能直接视作 kissqy Public Image R1 自带。不要照抄其 I²C 地址或私有补丁参数到未知板型。

## 现场安全配置（缺一不可）

- 严禁带电插拔总线/HAT/IMU，杜邦线临时搭接不能作为承载运动的永久电源线。
- 电源具备可触达的**硬开关/断电措施**、短路/过流保护；电源与线材、保险丝额定需根据实际最大负载选型。先从台架小负载限流测试，按测量结果分级放开，不能“一律电流最大”。
- 将鸭子机械固定/吊挂，所有脚和关节有活动空间、夹手点隔离，底部软垫防止跌落；另一人能在异常时立即撤电。
- 首次实验前明确软件启机行为：系统启动是否 auto-start `robotd`、是否默认 torque-on、看门狗/故障状态怎么切换；**由物理切断舵机供电提供最终兜底**。
- 若启动时舵机供电与主板供电同时由 HAT 分配，必须先验证 +5V 和 +BATT 电路隔离/转换；如果想 USB-C 与 HAT 双供电，必须明确 HAT 反灌路径得到设计证据并进行测量。未经验证严禁双源并接。
- 对实际 IMU 和固件版本建立记录；传感器没数据时运行时应拒绝进入 Policy，不允许绕过故障保护。

## G0：断电电气验收（全程拔下电池和 USB）

用万用表通断档逐条检查，不能只看线的颜色。记录**测试点→测试点、方向、测得电阻/通断、预期依据、照片**：
1. 电源输入 `+` / `-`、保险丝两侧/开关前后、舵机母线 V+/GND；
2. HAT 的 5V 输出、实际 Radxa 5V 入口及 GND；检查没有把 2S 直接送进主板的连接；
3. 舵机 3P 插口实际 DATA/V+/GND（以**该 PCB Rev 原理图+插头朝向**为准），确认不能因反插使供电落到 DATA；
4. IMU 供电电压、DATA 或 I²C/SPI 引脚，以及是否需要上拉/独立转换；
5. 活动关节拉到两端时，线不会夹断、绷紧或磨损外皮。

**GO：** 已形成 pin-to-pin 表，人工二次复核，所有疑点有来源。**NO-GO：** 找不到板版本原理图、有短路/极性不确定，立即停止，不上电。

## G1：不接 Radxa/舵机，独立检 HAT/稳压输出

仍不接电机和主板（仅保留 HAT 设计允许的供电路径），按原理图接实验限流电源，测：电源输入端、稳压器输出端的 +5V、3.3V 是否由主板提供还是 HAT 自带、静态电流/异常发热。所有读数记载空载与小负载测量条件。**不要因为看见“有 5V”就认定瞬态负载可承受**；无电子测量条件的高电流/波形项目应交给有经验的人实测，不能让 AI 自行判定合格。

**GO：** 电压在主板/HAT 规格内、稳定且温升正常，过流/切断机制有效。**NO-GO：** 出现热、异味、电压超规格，立刻断电并排查。

## G2：主控 + HAT（仍然不接电机总线电源）

选择**单一已核验的供电路径**给 Radxa 启动 Linux（可先维持原 USB-C 独立启动，随后在证实隔离时迁移至 HAT 5V）。先检查 `/dev/ttyS*`、I²C 实际设备映射、设备树、dmesg；不插舵机总线或启动 `robotd` 自动动作。

```bash
uname -m
ls -l /dev/ttyS* /dev/i2c-* 2>/dev/null || true
cat /proc/cmdline
systemctl list-units --type=service --state=running --no-pager
journalctl -b -p err --no-pager | tail -n 60
```

核对没有把 U-Boot/debug console UART 当作可自由使用的飞特 DATA 引脚。软件能看见串口 ≠ 线路电平/半双工收发电路已通过验证。

## G3：IMU + 全体舵机，**保持 torque OFF，只读**

- 在**断电**状态完成已通过 G0 的线路连接和机械固定，确认主板/舵机共地方式与 PCB 设计一致。让电源上限和连接线支持当前阶段。
- 上电前再次核查启动脚本/守护服务不会自动使能舵机；如做不到，应**保持舵机电源断开**直至修改启动行为并重新验收。
- 先读取 IMU 真实姿态/角速度/采样延迟；固定机身四方向倾斜检查轴向；超时/拔线（**断电后**模拟）应触发软件健康告警。
- 依次只读总线 15 个唯一 ID 的位置、电压、温度和通信错误；监测连续读数（建议至少 1–5 分钟），记录掉包、延时分布和 50 Hz 稳定性。若协议不匹配/数据漂移，立即回到 S2/S3，而不是降低保护门槛。
- 如安装了所选版本支持的 CLI，可运行 `robotctl version`、`robotctl health`、`robotctl monitor`，但要先确认这些命令属于**所安装版本**、不会触发 HOME/torque，`health` 报硬件未上力不等于软件安装失败。

**GO：** 稳态供电/IMU/15 只电机只读可复现，状态与视频/日志一致。**NO-GO：** 总线错包、ID 重复、IMU 超时或供电掉压。

## G4：受限单关节与 HOME（要现场看护）

先准备急停与支架，并把控制器中的关节 ID、方向、HOME、中间位置、机械限位、速度和力矩限制**按 S2 台账逐项核对**。先单个关节、极小指令、明确可中止的短时测试；记录目标/反馈/峰值电流/电压/温度，并实测轨迹与机械极限一致后才扩大范围。绝不直接对 15 关节同步发大幅度 HOME 命令。

更改舵机 P/D/转矩限制之前读出并备份全部原值，确认使用的是**已安装运行时中真正生效**的寄存器/部署 profile（有作者记录出现修改 TOML 不生效、运行时忽略 D 的情况）。不要借用其他样机的 P=3/D=0 或 IMU 补偿数字作为你机器的初始真值。

## G5：首次零速站立、低速行走

仅在 G0–G4 全通过、已知所选 HD1910 Policy 的 obs/action/归一化/关节顺序/动作缩放与部署固件一一相符时实施。首先低风险原地站立、人在支架旁，可即时撤电；从中立控制命令和最小受限动作开始，观察 IMU/关节误差与电压温度。记录受控时间、跌倒/重启/超时事件、原始日志与同步视频；恢复能力、高速动作、踢球翻滚一律放到独立的后续验证阶段。

### 出现异常的立即止损顺序

**撤销运动命令 → 在安全前提下卸力 → 用物理开关切断舵机供电**。如关节已经卡死/撞壳/线束冒烟，优先直接断电而非等待软件响应。待全部冷却/断电后检查、电气复测，保留失败记录；禁止自动重试使能。
