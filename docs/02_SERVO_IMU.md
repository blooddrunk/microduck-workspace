# 02 · HD1910 从一只舵机到整条总线、IMU（先只读）

**目的：** 先证明“USB 调试器 ↔ 单只 HD1910”的电气/协议链路，再扩展到 15 只和 IMU。首次阶段不装 Policy、不跑任何自动转动动作。

## 1. 先把三条概念区分开

- **机械零位**：关节实物的参考姿势，装错一齿/支架错位会变。
- **舵机编码器零点、ID、方向**：设备内部配置，不一定等于机械零位。
- **训练 HOME**：MJCF/Policy 所需的各关节默认角度，与编码器零点要经过映射才对应。**不能把 HOME=0 理解为所有舵机寄存器写 0**。

飞特 HD1910 使用飞特自有串行指令/寄存器；与 Dynamixel XL330 都能看作半双工总线舵机，但**同类接线形态不等于同一协议**。与原官方固件的总线/IMU 协议也不能直接互换。

## 2. 设备准备与断电检查

1. 找到**你购买的实际型号**的 FE-URT 串口调试器、对应的飞特 FD 调试工具/官方 SDK（可先参考 [飞特工具入口](https://github.com/fanhao375/microduck-replica/blob/master/docs/飞特资料/README.md)）。
2. 将**一只**未受负载/机械干涉的 HD1910 固定在安全台架。总线上不可同时存在其它舵机。
3. 查“调试器供电方式/USB 电源是否真的输出舵机 V+ / 逻辑电平范围”；不同 FE-URT 版本可能不同。**电脑 USB 不等于可靠的整机舵机电源。**
4. 查对应接头端视图：V+/GND/DATA 与电线颜色**逐根用万用表确认**，不要从图片推断 pin1；断电通断测试确认接地路径和无短路。
5. 将供电设置在舵机准确规格允许的范围；初次只有一只舵机、保持卸力，不启用动作。若无法确认适配器输出，不要连接。

## 3. 单舵机第一次通电：只读

通电后在 Windows 设备管理器确认 USB 串口的 COM 号，启动飞特官方 FD 调试工具，选择正确 COM 口、与实际固件匹配的波特率（社区的常见值 1 Mbps **不是无条件默认值**），先只读 Ping/Scan。

记录原始数据：**串口号、波特率、舵机 ID、工作模式、固件标识、反馈位置/速度/电压/温度、P/D/转矩配置（工具支持时）及通信错误**。保存截图或日志。

**验收**：能稳定读到且只有一只舵机，应答 ID 可解释；无过温、供电波动或误动作；不要求其运动。无法只读则**断电**依次排查：工具协议选择 → 供电 → GND/DATA → 端视图 → COM/波特率。严禁随机写 EEPROM、恢复出厂或刷固件“碰碰运气”。

## 4. 逐只建立 15 路关节台账（本轮只读）

每次**断电→换一只舵机→上电只读→记录→断电**。使用 [自动化教程](06_S0_S2_AUTOMATION.md) 的 [CSV 模板](../templates/hd1910_inventory.csv) 和 [独立映射模板](../templates/hd1910_mapping.json)。列名/单位以模板与自动化教程为准；缺字段 FAIL、未知值 BLOCKED，不填虚构数值。原先 `neutral_raw` 这种合并列不再使用，分别记录机械参考、编码器零点原值与训练 HOME（rad）。在 **开发电脑仓库根目录**执行静态验证，预期完整已确认数据的静态一致性 PASS；准备中空白项 BLOCKED，冲突 FAIL；它不执行任何设备读写。

先把身体关节列表从**实际装配图**逐一对到具体舵机。社区和官方例子常用：
右腿 10–14、左腿 20–24、头颈/嘴部 30–34，共 15 个；这只是**示例 ID 规划**，你必须保证映射跟所选运行时配置一致、没有重号。策略通常输出 **14 维动作**，第 15 个嘴部舵机不在这 14 维里，不能把 15 个电机直接“按数组下标”映射到动作输出。

**本轮不执行 ID/零点/模式写入。** 后续若取得真实硬件许可与参数确认，确需更改 ID：只连接一只、先备份配置，只写 ID，断电重连复读**新 ID**，随后检查旧 ID 已不存在；不要同时更改方向、零点、模式和增益。若不清楚工具中“写 EEPROM/锁定/解锁/中位校准”的含义，暂停并先查飞特手册。

## 5. 后续机械与方向、零点验收（本轮仅准备，不驱动运动）

舵机**卸力**状态下，在允许安全手动调整的机构上轻微摆动，不强行掰动受力或不可反驱关节；识别每个关节的正方向、几何极限、线束是否被拉紧。初次主动动作只能在确认限速/限角/急停后的专用校准工具内进行，单关节、极小偏移，人与机械保持安全距离；运动越过已知限位立即停。

记录“训练关节名 → 实物编号 → 舵机 ID → 正反号 → 中心偏置 → 合法运动区间”；不要直接使用其他作者的 15 颗舵机零点或控制增益。

## 6. S3 的 IMU 分支与通过标准（提前辨识，尚未验收）

| IMU 类型 | 最小检查 | 不可假定 |
|---|---|---|
| 躯干 `imu_to_dxl`，飞特总线固件 | ID / 协议 / 固件版本、gyro 和方向/时间戳，是否与 15 电机共线 | 官方 **Dynamixel ID 200** 的寄存器协议可直接给飞特 runtime 使用 |
| BNO085 等 I²C IMU | Linux 实际 I²C bus/address、稳定姿态/陀螺读数、线缆固定 | kissqy 预构建系统已自带该分支 |
| 自制/不明 IMU | 芯片丝印、PCB Rev、固件工程、接线图、上电电压 | 能出数据就满足 Policy 的坐标与延迟要求 |

IMU **方向正确还不够**：还必须检验静止偏置及安装角。把躯干固定在已知姿态，依次小幅前、后、左、右倾斜，观察方向变化和陀螺角速度符号；记录每个方向的“人为动作方向、传感器数值和预期符号”。将实际 HOME 姿态与运动学计算对比后再决定四元数补偿，**绝不能照抄别人测出的 8.54° 等数值**。

## 7. 阶段边界与下阶段

- S2 准备：逐只清点、只读原值、规划与未知项可审查。重号或标定缺口仍未验收，不为了拿静态 PASS 越级写参数/运动。
- S2 最终退出：15 颗舵机都有唯一可复读的 ID、名称映射和原始参数备份，机械方向/限位有现场证据；所需写入另经硬件许可与参数确认。
- S3/S5 另行验证 HAT/供电、IMU 与整条总线，不把单只只读结果等同于全量验收。
- 没有无控制抖动或通信错误暴增；相关数值、异常与失败也必须存档。
