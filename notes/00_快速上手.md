## 1. Microduck 是什么？生态由什么组成？

Microduck 是 [Pollen Robotics](https://github.com/pollen-robotics) 开源的**小型双足机器人**：
约 800 g 重、25 cm 高，14 个 Dynamixel XL330 舵机（左腿 5 + 头颈 4 + 右腿 5），
鸭子造型，头上有嘴（嘴尖可以点地捡东西）。它**用强化学习（RL）学会走路、站立、翻滚、踢球、轮滑**。

整个生态分三块，本工作区三样都有：

| 组成 | 仓库 | 语言 | 作用 |
|---|---|---|---|
| **训练** | `microduck_rl/` | Python | 在物理仿真里用 PPO 算法训练出控制策略（需要 GPU） |
| **运行时** | `microduck/`（浅克隆） | Rust | 跑在真机上的守护进程 `robotd`，负责加载/热切换 policy、驱动舵机 |
| **策略** | `policies/official/` | ONNX | 训练的产物，真机和仿真都能加载的"小脑" |

数据流：`microduck_rl` 训练 → 导出 ONNX →（发布到 HuggingFace）→ 真机 `robotd` 加载运行。
**我们在本地 play 的，就是真机上跑的同一份 ONNX 文件**，这是这个生态最妙的地方。

## 2. 五分钟概念速览（零基础）

- **policy（策略）**：一个神经网络。输入机器人当前状态（61 个数字），输出 14 个关节的目标角度。
  50 Hz 运行，即每秒决策 50 次。你可以把它理解成机器人的"小脑"。
- **observation（观测，61 维）**：policy 的输入 = 48 维本体感知（关节角度/速度、躯干姿态等）
  + 13 维指令（前进/侧移/转弯速度 3 个、头部姿态 4 个、身体姿态 6 个；用不到的槽位补零）。
  **所有 policy 共享同一套观测格式**，所以真机可以在行走/起立/特技之间随时热切换。
- **action（动作，14 维）**：policy 的输出，对应 14 个舵机的目标位置偏移。
- **ONNX**：通用的神经网络文件格式。训练框架（PyTorch）导出成 ONNX 后，
  任何环境（真机、CPU 仿真）都能用 `onnxruntime` 加载运行，不依赖训练代码。
- **MuJoCo**：物理仿真器，算重力和碰撞。`infer_policy.py` 用的是 CPU 版 MuJoCo，不需要 GPU。
- **sim2real**：仿真里训练 → 真机上运行的迁移。这个仓库的精华全在缩小 sim2real 差距：
  - **BAM 舵机模型**：不是把舵机当理想电机，而是建模到电压控制律、反电动势、摩擦（这是差距的主要来源）；
  - **域随机化（DR）**：训练时随机电池电压、指令延迟、摩擦大小，逼 policy 对不确定鲁棒；
  - **Backlash（齿隙）**：齿轮间隙 ±1° 也建到模型里（`-Backlash` 任务变体）。
- **PPO**：训练用的强化学习算法，不需要了解细节，只需知道它是"试错+奖励"的循环。

## 3. 现在就玩：play 官方 policy

**前提**：图形窗口依赖 WSLg（已确认可用，`DISPLAY=:0`）。
启动后会弹出一个 MuJoCo 3D 窗口显示机器人；**键盘输入要在终端里按**（窗口本身不接收按键）。

```bash
cd ~/research/microduck

./play.sh walk        # ① 最简单：走路 + 站立。第一次玩用这个
./play.sh velstand    # ② 官方默认步态：走路+站立+摔倒自己爬起来（推荐！按 P 随机推它一把试试）
./play.sh sitstand    # ③ 按 Y 坐下，再按 Y 站起来
./play.sh kick        # ④ 场景里有个球，按 K/L 左右脚踢它
./play.sh roulade     # ⑤ 按 R 前滚翻
./play.sh roller      # ⑥ 轮滑模式：脚底装了被动轮，滑着走
./play.sh full        # ⑦ 全家桶，上面的特技一次全加载
```

不想用脚本，等价的原始命令是（`play.sh` 就是它的包装）。
注意 **`--new-cmd-obs` 不能省**：官方 policy 全部是 61 维观测版，
而脚本默认构建旧版 51 维观测，缺了这个标志会报
`Got invalid dimensions for input: obs ... Got: 51 Expected: 61`：

```bash
cd ~/research/microduck/microduck_rl
uv run scripts/infer_policy.py --new-cmd-obs \
  --walking ../policies/official/velstand.onnx
```

### 键盘控制表（在终端里按，不在窗口里）

| 模式 | 键 | 作用 |
|---|---|---|
| 速度控制 | `↑` / `↓` | 加速 / 减速前进（0 = 停住滑行，负 = 刹车） |
| | `←` / `→` | 侧移（轮滑模式下是转弯） |
| | `A` / `E` | 左转 / 右转 |
| | `空格` | 全部指令清零（滑行停住） |
| 特技 | `Y` | 坐/站切换（sitstand） |
| | `G` | 蹲下嘴尖点地（ground pick） |
| | `K` / `L` | 左 / 右脚踢球 |
| | `R` | 前滚翻 |
| | `P` | 随机方向猛推躯干一把（测试摔倒恢复） |
| 视角切换 | `B` | 进入身体姿态模式：方向键/A/E 调躯干高度和俯仰侧倾，空格复位 |
| | `H` | 进入头部模式：方向键/Z/S 转头 |
| 其他 | `T` | 暂停/恢复 policy 推理（暂停时电机保持最后目标） |
| | `Q` | 退出 |

## 4. 本机环境是怎么搭的（备忘）

| 项 | 状态 |
|---|---|
| Python | 系统 3.14 太新，仓库要求 **3.12**；由 uv 自动下载管理，隔离在 `microduck_rl/.venv/` |
| 包管理 | [uv](https://docs.astral.sh/uv/)（安装在 `~/.local/bin/uv`），`uv sync` 已跑完（含 torch 等，约 3 GB） |
| 依赖验证 | 仓库自带 CPU 测试 **225 通过 / 1 跳过**（`uv run --with pytest pytest tests/`） |
| policy 验证 | 10 个 ONNX 全部下载；逐一实测输入均为 `[1,61]`、输出 `[1,14]`，与 manifest 契约一致 |
| 端到端验证 | `velstand` 与 `roller` 两个模式各实跑 20–30 秒：BAM 舵机模型、50 Hz 控制循环、WSLg 图形窗口全部正常（Ctrl+C/Q 退出） |
| GPU | **没有**（WSL2 无 NVIDIA GPU）。训练不可行，但 play 用的 `infer_policy.py` 是 CPU MuJoCo + ONNX，完全不受影响 |

日常只需要记住一个命令模式：在 `microduck_rl/` 目录下用 `uv run <脚本>`，
uv 会自动使用正确的 Python 和虚拟环境，不需要手动 activate。

## 5. 常见问题

- **窗口没弹出来 / 报 display 错误**：确认 WSLg——`echo $DISPLAY` 应输出 `:0`。
  从 Windows Terminal 重新打开 WSL 终端通常就能恢复。
- **按键盘没反应**：焦点要放在**启动脚本的终端**里，MuJoCo 窗口不接收按键。
- **`uv run` 报找不到命令**：`~/.local/bin` 不在 PATH，用绝对路径 `~/.local/bin/uv run ...`，
  或在 `~/.zshrc` 加 `source $HOME/.local/bin/env`。
- **机器人自己抖/摔倒**：正常，policy 是在域随机化下训练的，个别种子会翻车；
  重启脚本即可（初始化会回到站立 keyframe）。
- **我想训练自己的 policy**：本机无 GPU 不行。两个选择：
  1. 仓库自带的云端方案：`uv run train <任务> --hf-jobs`（Hugging Face Jobs，见 `microduck_rl/scripts/hf/README.md`）；
  2. 找一台有 NVIDIA GPU 的机器再 `uv sync`。
