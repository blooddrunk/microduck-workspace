## 需重点辨析的兼容问题

- **C1 HAT / 连接器**：官方 HAT README 规定由**电机连接器作为供电入口**；三针 TTL `J13/J14`、四针 RS485 `J3/J11` 不能互换，`Speak` 两针绝非电池输入。HAT 下游给 ZERO 3W 的 5V 尚未实测；电池满电 8.4V 不能直接到 ZERO 的 5V。
- **HD1910 2048**：4096 steps/turn 的位置计数使 2048 成为常用软件零位。中位校准是将**执行校准时的当前轴姿态**设成参考读数；参考姿态不对，读数可为 2048 但机械零位错误。官方训练 HOME 包括关节非零角度，不能把 HOME 当成所有舵机的 2048。重做前先只读每颗实际 ID、零位操作时姿态与当前反馈。
- **IMU/FT6**：kissqy FT6 源码 `duck-control/src/feetech.rs` 的 `IMU_IDENTITY=[6,0,0,0,0xF2]`，向 ID200 读寄存器 0 长 5；飞特 `SYNC_ADDRESS=56`、`SYNC_LENGTH=15`，状态位按 FT6 合同处理。购买的第三方 IMU 文档**未声明这个身份签名或 FT6 所需的全部 bit 语义**。所以双协议与 ID200 不等于可以直接用 kissqy Public Image。
- **IMU 角速度系数**：购买文档明确 `deg/s = int16 / 16.4`，kissqy 的 SFLP decoder `0.0175 deg/LSB`。如果原始值定义确实按文档，则两者相差约 **3.48 倍**；不能直接复用。需采集已知转动角速度，核对主控代码路径/量程和编码格式。
- **IMU 电源**：卖家文档截图**未给出 VCC 允许电压**，不允许直接把模块插到带 2S 电池的 HAT 电机总线上试探。需要实物型号、商家电压规格和万用表。
- **Radxa V1.12 镜像**：fanhao375 在 2026-10-12 镜像分析中报告 V1.12 可能与 kissqy R1 的 Armbian 主线 U-Boot 不兼容，曾需瑞莎引导才能启动。属于**社区特定板的记录**，不是你这块板已失败的证据。先用纯净受支持的板型镜像独立 5V 启动，再决定镜像路径。
